# DropoutGuard project audit

Audit of the whole repository at commit `ab739b3` (branch `fix/phase6`), 2026-10-03.
Every finding below comes from a command that was run or a line that was read during the audit;
nothing is estimated. No tracked file was changed. Side effects: the throwaway test database was
migrated and seeded with 200 students for the browser check, and the test runs rewrote the gitignored
`data/synthetic/indian_college_students.csv` (see H2).

**Severity:** **High** = a test or verification gate fails, a reader or mentor is told something
false, or data is exposed if deployed. **Medium** = behaviour is silently wrong, ignored or against
a project rule. **Low** = maintainability, deprecations, cosmetics.

## 1. Failing tests (product suite)

### T1 · High · Coefficient-recovery test fails on the sign of `is_first_generation`
- **Where:** `ml/tests/test_data_pipeline.py::TestGeneratorCoefficientRecovery::test_generator_recovers_configured_coefficients`
- **Evidence:**
  ```
  AssertionError: wrong sign: ['is_first_generation']; CI misses configured value: []
      is_first_generation   configured=+0.02471 estimate=-0.00570 CI=[-0.05716, +0.04576]
  ```
  All 16 nonzero configured coefficients lie inside their Bonferroni-adjusted 95% intervals; only
  this sign check fails. The configured effect is so small that its interval contains 0, so the sign
  of the point estimate is noise at n = 200,000.
- **What to do (owner decision):** require the sign check only for coefficients whose adjusted
  interval excludes 0, or fix a larger n in advance and rerun. Do not change the seed to make it pass,
  and do not widen the interval. This one failure also makes verification V1.3 fail (V2 below).

## 4. ML and simulation correctness

### M1 · High · The attendance effect is documented as a 75% hinge but implemented as linear
- **Where:** `ml/simulation/assumptions.yaml:44-47` vs `ml/data_pipeline/generate_synthetic_indian.py:391`
- **Evidence:** the yaml note (published in `docs/simulation.md`) says *"Penalty for attendance deficit below
  statutory 75% rule (log-odds increase of 0.040 per percentage deficit)"*; the generator adds
  `b_att_pct * attendance_percentage` for every student, over the whole 10–100% range, with no 75% hinge.
- **What to do (owner decision; changes the simulated labels):** either correct the note to "linear,
  per percentage point", or implement `max(0, 75 − attendance)` with a positive coefficient; then rerun
  `python -m ml.pipeline run-all`.

### M2 · Medium · Generator parameters hardcoded outside `assumptions.yaml`
- **Where:** `ml/data_pipeline/generate_synthetic_indian.py`
  - `:137` silently falls back to `0.355` if the base rate is missing from the yaml
  - `:242` lab-attendance clip floor `15.0` (the other subjects use `attendance_min`)
  - `:247-249` monthly attendance noise SD `4.0`
  - `:296` backlog-rate floor `0.05` and attendance threshold `65.0` (the yaml note mentions 65% but there is no key)
  - `:315` engagement weights `0.5` / `0.5`
  - `:344` forum-participation floor `0.2`
- **Evidence:** these never appear in `assumptions.yaml`, so `docs/simulation.md` (rendered from it)
  does not show them.
- **What to do:** move each into `assumptions.yaml` with a `source` label; remove the `0.355` fallback so a
  missing value fails loudly.

### M3 · Medium · Predicted risk is not monotonic in attendance
- **Evidence:** profile `STU_03_BORDERLINE_COMMUTE`, current committed model. Overall, course and monthly
  attendance were scaled together (3-month trend and 75% flag recomputed; all other inputs fixed):

  | attendance | 50% | 60% | 65% | 70% | 75% | 80% |
  |---|---|---|---|---|---|---|
  | probability | 0.3695 | 0.3977 | 0.3893 | 0.1917 | 0.1564 | 0.1878 |

  Improving attendance can raise the score (50→60%, 75→80%), while the recourse engine recommends
  raising attendance.
- **What to do (owner decision; changes the model):** add XGBoost `monotone_constraints` for the attendance
  features and a monotonicity test, or document the limitation.

### M4 · Medium · Three simulation parameters still have no citation
- **Where:** `ml/simulation/assumptions.yaml:4` (`target_base_rate` = 0.355), `:132` (`gender_proportions`),
  `:205` (`income_slab_proportions`), all `source: "TODO(citation)"`.
- **What to do:** find a published source for each, or keep the placeholder and keep flagging it.

### M5 · Medium · The OULAD GRU baseline is dropped silently when PyTorch is missing
- **Where:** `ml/evaluation/harness.py:282-288`
- **Evidence:** `if HAS_TORCH:` adds the GRU; otherwise nothing happens, and an exception is only logged as
  a warning. The benchmark JSON would then lack the GRU row without failing. PyTorch is pinned in
  `requirements.lock`.
- **What to do:** raise an error when the GRU is requested and PyTorch is unavailable.

### M6 · Low · Recourse ignores SHAP failures
- **Where:** `ml/intervention/engine.py:409-410` (`except Exception: pass`)
- **Evidence:** if the explainer fails, plans are chosen without SHAP alignment and nobody is told.
- **What to do:** log and re-raise, or return an explicit "drivers unavailable" flag.

### M7 · Low · Dead variables in ML code
- **Where:** `ml/intervention/engine.py:377` (`target_threshold`), `ml/models/fairness_audit.py:232-234`
  (`g_cv`, `inc_cv`, `fg_cv`), `scripts/render_benchmark_report.py:296` (`t_values`).
- **What to do:** remove them, or use them where they were intended.

## 5. Mentor-facing output and product language

### P1 · High · The Low-tier recourse text can be false for the student it describes
- **Where:** `ml/intervention/engine.py:391`, returned to API clients as `counselor_summary`
  (`backend/app/schemas/intervention.py:84`)
- **Evidence:** the text is hardcoded: *"Student is performing exceptionally well across all 4 pillars and
  remains in the Low Risk tier (prob < 33%)."* `STU_03_BORDERLINE_COMMUTE` (overall attendance 55.4%,
  debarment flag 1, calibrated probability 32.3%) receives exactly this text. On the live API with 200 seeded
  students, 36 of the 127 Low-tier students have attendance below 75%; for `IND_2026_0190` (attendance 44.6%)
  `GET /api/v1/students/IND_2026_0190/interventions` returns this summary plus *"No urgent intervention
  required"*, while the student page lists "Mandatory Attendance Counseling & Faculty Mentor Check-in" under
  Recommended Support Interventions. The current frontend does not display `counselor_summary`, but every
  API client receives it.
  "(prob < 33%)" also ignores the configurable `RISK_THRESHOLD_LOW`.
- **What to do:** build the message from the student's data (for example, name any statutory flag such as
  attendance below 75%), take the threshold from config, and do not hide rule-based flags because the
  tier is Low.

### P2 · Medium · "Dropout prediction" wording that the project's own UX spec bans
- **Where:** `README.md:1`; `scripts/render_fairness_report.py:310` (and so `docs/ethics_and_fairness.md`);
  `backend/app/main.py:57` (OpenAPI description); `ml/validate_pipeline.py:69`;
  `frontend/src/pages/UniversalPredictor.jsx:250,342`; `.gitignore:1`.
- **Evidence:** `docs/frontend_ux_spec.md:30` lists "predicted dropout" as wording to avoid; CLAUDE.md rule 10
  says "flags students who may need support", never "predicts who will drop out".
- **What to do:** reword (for example "early-warning and support system"); regenerate the ethics doc
  through `python -m ml.pipeline run-all`.

## 6. Backend API

### B1 · High (deployment blocker) · No authentication on any endpoint
- **Evidence:** no auth dependency, API key, OAuth or `Security(...)` anywhere in `backend/app`. Student
  records, predictions and intervention logs can be read and written by anyone who can reach the API.
- **What to do (scope decision):** add authentication and per-mentor authorisation before the API is
  reachable beyond localhost.

### B2 · Medium · CSV upload is read fully into memory before any size check
- **Where:** `backend/app/api/v1/endpoints/predict.py:113` (`pd.read_csv(io.BytesIO(file.file.read()))`)
- **Evidence:** the only limit is `MAX_BATCH_SIZE = 1000` rows (`backend/app/schemas/prediction.py:34`),
  checked after parsing; there is no byte limit.
- **What to do:** reject uploads over a byte limit before reading (the limit is a product decision).

### B3 · Medium · A malformed mentor-queue cursor silently restarts at page 1
- **Where:** `backend/app/services/mentor_queue_service.py:44-46` (decode errors → `None`), used at `:143`
- **Evidence:** a corrupted cursor is treated as "no cursor", so the client gets page 1 again and can
  show duplicates. Live check: `GET /api/v1/mentors/queue?cursor=not-a-valid-cursor` → HTTP 200.
- **What to do:** return HTTP 422 for an undecodable cursor.

### B4 · Low · Deprecated status constant
- **Where:** `backend/app/core/errors.py:111,122,129`
- **Evidence:** test warning: *"'HTTP_422_UNPROCESSABLE_ENTITY' is deprecated. Use
  'HTTP_422_UNPROCESSABLE_CONTENT'"* (Starlette 1.6.0).
- **What to do:** use `status.HTTP_422_UNPROCESSABLE_CONTENT`.

### B5 · Low · Test client transport is deprecated
- **Evidence:** test warning: *"Using `httpx` with `starlette.testclient` is deprecated; install `httpx2`
  instead"* (httpx 0.28.1, Starlette 1.6.0).
- **What to do:** plan the switch; it is a dependency change, so it needs approval.

### B6 · Low · The universal endpoint returns raw exception text as a 400
- **Where:** `backend/app/api/v1/endpoints/universal.py:46-47` (pending-decision code)
- **Evidence:** `raise HTTPException(status_code=400, detail=f"Inference error: {str(e)}")` sends internal
  error text to clients and turns server faults into client errors (ruff B904).
- **What to do:** if the endpoint is kept, log the exception and return a generic 500.

## 7. Configuration

### C1 · Medium · `RISK_THRESHOLD_LOW/HIGH` and `RANDOM_SEED` in `.env` are ignored by the running API
- **Where:** `ml/config.py:26-27,39` read them with `os.getenv`; `.env.example:36-37` documents them.
- **Evidence:** the `Settings` class (`backend/app/core/config.py`) has no such fields, and nothing in
  `backend/app` or `ml` loads `.env` into the process environment. The test conftests do call
  `load_dotenv`, so tests and a running server can use different thresholds. `LOW < HIGH` is never validated.
- **What to do:** read them through `Settings` (validated `0 < LOW < HIGH < 1`) and pass them to
  `ml.config`, or load `.env` in `ml/config.py`.

### C2 · Low · Machine-specific type-checker config
- **Where:** `pyrightconfig.json` hardcodes `/Users/dhrupal/...` paths; `pyproject.toml` has a second
  `[tool.pyright]` block.
- **What to do:** use relative paths and keep one config.

### C3 · Low · `pytest.ini` hides a NumPy deprecation that comes from joblib
- **Evidence:** with the filter overridden, the warning comes from
  `joblib/numpy_pickle.py:207` (`array.shape = self.shape`) while loading the pickled models; it will
  break when NumPy removes shape assignment.
- **What to do:** upgrade joblib when a fixed release exists; keep the filter scoped to joblib.

## 9. Repository hygiene

### H1 · Medium · Model binaries and generated CSVs are tracked in git
- **Evidence:** 15 `.joblib` files under `ml/artifacts/universal/` and 5 CSVs under
  `data/processed/universal/` are tracked (CLAUDE.md rule 6). `.gitignore` uses `ml/artifacts/*.joblib`
  and `data/processed/*.csv`, which only match the top level of those folders.
- **What to do (after the universal-engine decision):** use `ml/artifacts/**/*.joblib` and
  `data/processed/**/*.csv`, then `git rm --cached` the files.

### H2 · Medium · The test suite writes a cohort CSV inside the repository
- **Where:** `ml/data_pipeline/feature_engineering.py:205` calls the generator without `output_path`, so it
  writes `data/synthetic/indian_college_students.csv`; `verification/test_v6_phase3.py:80,114` call the
  generator the same way, and `verification/test_v7_phase4.py:41` reaches it through feature engineering.

  rewrote that file from 2,001 to 301 lines. No code reads it, but its contents depend on which test ran last.
- **What to do:** pass `output_path=None` (or a temp path) in the generator calls in
  `feature_engineering.py` and `test_v6_phase3.py`.

### H3 · Medium · Rule and task files are where CLAUDE.md does not look

  `docs/tasks/phase6_fixes.md` and `docs/ui_redesign_spec.md`.
- **What to do:** move them to the paths CLAUDE.md names (and decide whether to track them), or update CLAUDE.md.

### H4 · Low · Unused code reported by ruff
